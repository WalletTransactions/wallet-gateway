# Proposal

## Why

wallet-ai отдаёт ход задания `chat` потоком `text/event-stream`
(`GET /api/ai/jobs/{id}/events`, change `chat-sse-events` в wallet-ai), но
гейтвей буферизует ответ апстрима целиком и отдаёт клиенту одним куском. Без
потокового прокси побуквенный вывод во внешнем трафике невозможен: клиент
получил бы весь поток разом, когда он уже закончился.

## What Changes

- Потоковый режим проксирования: если клиент прислал `Accept: text/event-stream`
  на `GET`, а апстрим ответил 2xx `text/event-stream`, гейтвей пересылает тело
  кусками по мере прихода, без буфера и без сжатия.
- Любой другой ответ на такой запрос (404, 429, JSON, ошибка апстрима)
  проксируется как раньше, целиком.
- Таймаут чтения маршрута действует между кусками, а не на весь поток; общего
  дедлайна нет. Обрыв клиента закрывает соединение с апстримом.
- Лимит одновременно открытых потоков гейтвея (`GATEWAY_STREAMS_MAX`):
  каждый занимает поток пула. Сверх лимита — 503, пул растёт на лимит.
- Требование «Ответ буферизуется целиком» из `proxy-forwarding` получает
  исключение для потоков.
- JWT проверяется один раз при открытии; срок жизни токена внутри открытого
  потока не отслеживается (поток ограничен заданием, ≤ 120 с плюс TTL).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities
- `proxy-forwarding`: поток `text/event-stream` отдаётся по мере прихода;
  лимит открытых потоков; сжатие и буферизация для потока отключены.

## Impact

- Код: `src/main.cpp` (`proxy_request`, `handle_proxy`, размер пула, переменная
  окружения), `README.md`, `openapi.yaml` (замечание у `/api/ai/*`).
- Зависимости: wallet-ai (`AI_STREAM_ENABLED`) включается после выкладки
  гейтвея; клиентам (бот, web, Android) нужно слать `Accept: text/event-stream`.
- wallet-infra: `GATEWAY_STREAMS_MAX`, при необходимости сборка образа.
- Метрики и access-лог: запись о запросе появляется после закрытия потока, а
  `duration_ms` равна длительности потока.
